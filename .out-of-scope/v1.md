# Out of scope for Komodash v1

This file documents what v1 **deliberately does not do**. Each item is listed because someone has reasonably suggested it, or because a future contributor will reasonably wonder why we don't do it. The point is not to forbid these features forever — most are good ideas — only to keep the v1 surface small enough to ship.

The reasoning behind each is recorded either here or in the linked ADR.

## Feature surface

- **Custom Layout authoring.** Writing new tiling algorithms inside Komodash. Komorebi accepts custom layouts via JSON; surfacing a designer for them is a sub-project of its own.
- **Custom bar widget development.** Authoring new bar widgets. The Bar configuration editor edits *which* widgets show and *how*, not *what widgets exist*.
- **Themes / custom CSS for Komodash itself.** v1 is one design.
- **First-run dashboard tour.** Callout-style onboarding tours rarely earn their build cost. The sidebar is short and self-evident.
- **"What's new" / changelog page.** Add when there is something material to announce.
- **System-tray / background-process mode.** Komodash is a foreground app. It does not need to be running for Komorebi to work; it is an editor, not a daemon.
- **Drag-and-drop window movement in the Dashboard.** Cool gesture; meaningful gesture-infrastructure build. Right-click → "Send to workspace" is the v1 affordance.
- **Multi-instance Komodash.** Enforced single-instance via Windows mutex — see [ADR-0008](../docs/adr/0008-single-instance-via-mutex.md).
- **Profile switching / multiple config sets per user.** One **Static configuration**, one **Bar configuration**, one `whkdrc` per user. Profiles is a real feature, but it is its own feature.
- **Cloud sync of configs.** Dotfiles managers already do this. We do not.
- **Plugin / extension API.** No public extension surface in v1. The **Field catalog** is the closest analogue and it is Komodash-bundled.

## Detection / validation

- **Per-application reserved-chord detection.** Knowing that Discord eats `ctrl+shift+p` requires a hand-maintained list that would always be wrong — see [ADR-0009](../docs/adr/0009-hotkey-validation-scope.md).
- **OS-API hotkey-collision check on capture.** A future enhancement could try to register the chord and see if Windows rejects it. Out of v1 for scope.

## Distribution / lifecycle

- **Automatic Komodash updates.** v1 shows a "new version available" banner that opens the GitHub release page — see [ADR-0011](../docs/adr/0011-v1-ship-posture.md). Tauri's signed auto-updater is planned for v1.x.
- **Automatic Komorebi upgrades.** Komodash exposes a "Check for Komorebi update" button that wraps `winget upgrade LGUG2Z.komorebi`. We never run it silently.
- **Code-signed binaries.** v1 ships unsigned — see [ADR-0011](../docs/adr/0011-v1-ship-posture.md).

## Privacy / observability

- **Telemetry / analytics / remote crash reporting.** Nothing leaves the user's machine in v1. Logs are local. A privacy doc and an opt-in mechanism would be required before that posture changes — see [ADR-0011](../docs/adr/0011-v1-ship-posture.md).

## Platform / language

- **macOS / Linux ports.** Komorebi itself is Windows-only.
- **Multi-language UI.** English only. The strings live in a single file that could later be wrapped in i18n, but no other locale ships in v1.
